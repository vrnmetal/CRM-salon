# Салон — SaaS CRM для салонов красоты (каркас / фундамент)

Рабочее имя `salon` (бренд выберем позже). Это **фундамент** — несущий слой, на
который дальше навешиваем фичи модулями. Фич пока нет намеренно: сначала стена.

## Что уже внутри (каркас)

- **Мультитенантность** (`tenant_id` + row-level изоляция). Бизнес-модели наследуют
  `core.managers.TenantModel` → автоматически фильтруются по текущему тенанту.
  `objects` — только свой тенант, `all_objects` — сквозной (провайдер/фон).
- **Права (permission-first, deny-by-default).** Реестр атомарных прав
  (`core/permissions.py`), декоратор `@requires("code")` защищает действие на
  сервере, роли = пресеты поверх реестра, UI «Настройки доступа» строится из
  реестра автоматически. Скрипт `scripts/check_permissions.py` проверяет покрытие.
- **Подсказки (hints-first).** Реестр текстов (`core/hints.py`), тег `{% hint %}`,
  тумблер показа в профиле пользователя, тач-совместимость (долгий тап).
- **Модульная сборка.** Реестр модулей (`core/modules.py`): ядро включено всегда,
  остальное — по флагам на тенанте (`Tenant.enabled_modules`). URL модулей
  монтируются в корневой `config/urls.py` только если модуль реализован.
- **Дизайн-система.** `static/css/app.css` — нейтральная премиум-палитра + токены;
  акцент (`--accent`) подменяется под бренд тенанта (white-label) инлайном в
  `base.html`. Сайдбар слева, единый `app.css` везде.
- **Базовые модели:** `Tenant`, `User` (с тенантом/ролью/флагами), `Role`, `AuditLog`
  (append-only). Провайдерский слой заложен (`is_provider_admin`, impersonation-право).

## Стек

Django 6 + HTMX (подключим на фичах) + Bootstrap-подход по CSS (свои токены) +
PostgreSQL 16 + Docker. Python 3.13.

## Развернуть локально (ВСЁ локально, прод не трогаем)

```bash
# 1. Распаковать архив в папку с проектами (пример: /home/root-dm)
cd /home/root-dm && unzip -o salon.zip

cd salon

# 2. Окружение
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env           # при желании поправить (НЕ ставить пробелы после =)

# 3. База в Docker
docker compose up -d db

# 4. Миграции + демо-данные + вход
python manage.py migrate
python manage.py seed_demo     # создаст демо-тенанта и пользователей
python manage.py createsuperuser   # опционально, для /django-admin/

# 5. Запуск (порт 8001, чтобы не пересекаться с ремонтной CRM на 8000)
python manage.py runserver 8001
```

Открыть http://127.0.0.1:8001/ и войти:
- `owner` / `demo12345` — собственник (видит дашборд)
- `admin` / `demo12345` — администратор (видит журнал)
- `master` / `demo12345` — мастер (минимум прав)

Пароль у демо-пользователей — `demo12345`.

### Быстрый старт без Docker
В `.env` выставить `DB_ENGINE=sqlite` — поднимется на sqlite-файле, Postgres не нужен.

### Залить в git (новый приватный репозиторий)
```bash
cd salon
git init && git add . && git commit -m "Каркас: мультитенант, права, подсказки, дизайн-система"
git branch -M master
git remote add origin <URL-нового-приватного-репо>
git push -u origin master
```

```bash
python manage.py check

```

## Известные грабли (учтены в коде, не повторять)

- `USE_HTTPS` — **отдельный** флаг в `.env`, НЕ завязан на `DEBUG`. Локально по http
  держать `0`, иначе secure-куки рвут логин.
- В `.env` **нет пробелов после `=`**.
- URL модулей монтируются через реестр модулей (не все в одном файле вручную) —
  это осознанное отличие от ремонтной CRM ради модульности.
- Фильтр `can` и тег `hint` требуют `{% load core_extras %}` в каждом шаблоне,
  который их использует (в т.ч. в наследниках `base.html`).
- Инфраструктурные модели (`Tenant`, `User`, `Role`, `AuditLog`) НЕ изолируются
  менеджером (нужны при логине/провайдеру) — фильтруем их по тенанту явно.
  Авто-изоляция — только для бизнес-моделей на `TenantModel`.

## Что дальше (по плану)

Журнал + быстрая запись (3 поля) → клиенты с профилем-сводкой → дашборд-советник.
Модули (склад/тех.карты, ЗП, финансы, абонементы) — волнами поверх каркаса.

## Соседство с ремонтной CRM на той же машине

Проекты изолированы (свои папки, `.venv`, Docker-тома `salon_*` vs `crm_*`).
Пересекаться могут только хост-порты, если запускать оба РАЗОМ — поэтому салон
сдвинут: **Postgres 5433** (у ремонтной 5432), **runserver 8001** (у ремонтной 8000).
По очереди работают и без этого; со сдвигом — можно держать оба одновременно.

## Структура

```
config/        настройки, корневой urls, wsgi/asgi
core/          каркас: tenancy, permissions, hints, modules, модели, middleware
  management/  команда seed_demo
  templatetags/ теги can/hint
templates/     base.html + страницы ядра
static/css/    app.css (дизайн-система)
scripts/       check_permissions.py
```
